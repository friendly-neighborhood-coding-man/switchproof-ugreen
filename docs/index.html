The problem

A copy-complete message is not a migration audit.

When moving from an established NAS platform, users need confidence that their file data is still there. SwitchProof separates what was observed from what was merely assumed.

≠

Names aren't content

A familiar file path doesn't prove the bytes match. The proposed workflow uses hashes and metadata as evidence.

◎

Coverage isn't automatic

Limited listings, inaccessible folders and unknown counts should never become an invented 100% result.

⌁

Uncertainty matters

Incomplete or ambiguous observations are reported honestly, rather than disguised as a successful migration.

Orchestrated, not scripted

Six gates. One evidence standard.

SwitchProof is a SKILL.md workflow designed for Uliya's supported expert agents — not a standalone executable plugin.

GATE 00

Preflight

Confirm authorized, accessible roots and reject overlapping source/destination paths.

GATE 01

Discover

Enumerate what the tools actually return, tracking truncated or uncertain listings.

GATE 02

Verify

Collect file metadata and SHA-256 evidence before and after inspection.

GATE 03

Reconcile

Match file occurrences one-to-one, accounting for renamed paths and duplicates.

GATE 04

Audit

Apply conservative completion rules; never promote missing evidence into success.

GATE 05

Report

Explain verified scope and limitations. Save a report only with user approval.

Clear outcomes

Four results. No false certainty.

VERIFIED

All required file occurrences in a nonempty, defined scope have complete matching evidence.

MISMATCH

Complete, trustworthy evidence shows missing or modified file content.

INCOMPLETE

Coverage or evidence is missing, unstable or ambiguous.

BLOCKED

A required path, authorization or other prerequisite is unavailable.

What it does not claim

Matching file hashes do not prove preservation of user permissions, application data, album metadata, snapshots or successful recovery. A “VERIFIED” result applies to its explicitly defined file-content scope only. The real UGREEN runtime, file-agent responses and third-party share access remain untested.
